# MergeTrip 

> **「行きたい」の発見から、計画のすり合わせ、旅の思い出保存までを一元管理する旅行計画アプリ**

React Native (Expo) で開発した、完全ローカル完結型の旅行計画・思い出アルバムアプリです。旅行計画の手間を削り、同行者とのスムーズな共有と記憶の記録をサポートします。

##  開発背景と解決したい課題

旅行の計画から終了後にかけて、以下のような課題を感じたことから本アプリを開発しました。

1. **計画作成の入力ハードルの高さ**
   - 行きたい場所の情報を1から手入力するのが面倒。
2. **同行者との意見調整・提案の難しさ**
   - 誰かの提案に対して「決定」か「保留」かが曖昧になり、スケジュール調整が難航する。
3. **旅行後の写真整理の形骸化**
   - 撮った写真がフォルダに埋もれ、どの日のどの予定の写真かが分からなくなる。

###  解決アプローチ
- **日常**: WEBサイトやSNSで見つけたURLから情報を自動取得して「行きたいリスト（ストック）」に登録。
- **計画時**: ストックから引用してタイムラインへ一発配置。同行者からの提案を「承認/保留/削除」できる直感的なステータス切り替え（River UI）を導入。
- **旅後**: 各予定や日にちごとに写真を紐付け、タイムラインと連動した「思い出アルバム」へ自動昇華。

##  主な機能

### 1.  ストック機能（行きたい場所リスト）
- OGP（Webページのメタ情報）解析により、URLを入力するだけでタイトルや画像を自動抽出・保存。
- 観光、グルメ、宿泊などのカテゴリ別に整理し、計画作成時に1タップで引用可能。

### 2.  タイムライン型スケジューラー
- **付箋型カードUI**: 時間・予算・移動手段・メモを一目で把握できるカードデザイン。
- **提案・承認システム**: 送られてきた予定を「確定（左側）」「提案/保留（右側）」に振り分けて管理。
- **ギャップ表示**: 予定と予定の間の移動時間や空き時間を自動計算して可視化。

### 3.  柔軟な共有・データ連携
- **QRコード共有**: ネットワーク環境に依存せず、QRコードで1日分の予定やプロジェクト全体を友達へ引継ぎ。
- **クリップボード連携**: テキストデータとしてLINE等で簡単にやり取り可能。
- **PDFしおり生成**: 印刷やオフライン閲覧用に、写真付きの「旅のしおり」PDFを出力。

### 4.  思い出アルバム機能
- 日付や各付箋（予定）に紐付いた写真を一覧表示。
- 写真をタップすることで、その写真を撮影した日・場所のタイムラインへダイレクトにジャンプ。

### 5.  安心のデータ管理
- 完全ローカルストレージ駆動（オフライン動作可能・プライバシー安心）。
- **バックアップ/復元**: 全データ・全写真をZipファイル形式で丸ごとエクスポート/インポート可能。
- 不要画像の自動削除（データお掃除機能）を搭載。

## 🛠 現在の設計課題と今後の改善ロードマップ (Technical Challenges & Roadmap)

本プロダクトは、実体験に基づくプロトタイプ検証と高速開発を優先して構築されました。現在は基本機能の実装を完了し、保守性・パフォーマンス・型安全性を高めるセカンドフェーズ（リファクタリング）へ向けた課題を以下のように整理・設定しています。

### 1. アーキテクチャとコンポーネント構造の最適化
- **現状の課題**: UI描写・状態管理・ストレージ読み書き・外部解析（ICS解析等）のロジックが `index.tsx` に集約されており、Fat Component 化している。
- **改善アプローチ**: 
  - `components/`: UIパーツ（各モーダル、日別カード、タイムライン項目など）の切り出し
  - `hooks/`: ストレージ操作やカメラ制御などのカスタムフック化
  - `utils/`: ICS解析や日付フォーマットなどの純粋関数の分離

### 2. 型安全性（Type Safety）の確立
- **現状の課題**: プロトタイピングのスピード向上を目的として、一部で `// @ts-nocheck` を適用している。
- **改善アプローチ**:
  - `types/index.ts` にプロジェクト全体のデータ型（`Project`, `ScheduleItem`, `Accommodation`, `StockItem` 等）を厳格に定義。
  - 型チェックを有効化し、実行時エラー（`undefined` アクセス等）を静的解析段階でゼロにする。

### 3. パフォーマンスと状態管理（State Management）の改善
- **現状の課題**: トップレベルコンポーネントでの大量の State 保持により、局所的な入力やモーダル操作時にも全体再レンダリングが発生する可能性がある。
- **改善アプローチ**:
  - コンポーネントの局所化および `React.memo` や `useCallback` の活用による不要な再レンダリングの抑制。
  - 大量画像や Base64 変換処理（PDF生成・バックアップ）実行時のメモリ使用量の最適化。

### 4. 保守性と品質保証（Quality Assurance）
- **現状の課題**: 自動テスト（Unit/Integration Test）が未導入。
- **改善アプローチ**:
  - 日付計算や ICS 解析などの核心ロジックに対する Jest によるユニットテストの導入。
  - CI/CD（GitHub Actions）を活用した自動ビルド・型チェック環境の構築。
